# QualiCode Sprint 4 交付说明

日期：2026-09-20

## 产品任务

- 开放编码建议现在停留在开放编码阶段，不会在 DeepSeek 返回后直接进入确认页。
- 用户可以逐条接受、修改或删除建议，也可以一键接受全部建议。
- 只有所有未删除建议都已处理后，才能进入开放编码确认；确认后才允许进入轴心编码状态。
- 每条编码展示锁定文本原文、证据卡片、临时检索命中说明，并支持跳回原文高亮位置。

## 前端任务

- 新增 SourceTextView，将锁定文本按编码片段渲染为可定位的原文视图。
- 新增开放编码 review 控件和确认按钮。
- 新增证据卡片，显示原文片段、chunk ID 和检索相关性。
- sessionStorage 兼容旧快照：没有 evidence 字段的旧会话按空数组恢复。

## 后端任务

- 新增临时文本分块和关键词/中文双字符 Top-K 检索模块 src/lib/rag.ts。
- 开放编码接口返回原文证据与临时 chunk 证据，并将 evidenceIds 写入编码对象。
- 新增 POST /api/evidence/search，按 textVersion 校验锁定文本，返回本次请求内生成的 chunks 和 evidence。
- 检索结果只存在请求内，不使用数据库、文件存储或长期向量库。

## 测试任务

- 增加 RAG 分块偏移量和 Top-K 排序测试。
- 增加证据检索 API 的成功与过期 textVersion 测试。
- 更新状态机测试，覆盖逐条接受、未处理建议不能完成、确认后进入 AXIAL_CODING。
- 更新开放编码接口测试，验证 evidenceIds 和证据集合返回。

## 教学任务

Sprint 4 的关键概念是：先把访谈文本切成带字符偏移的临时 chunks，再用轻量词法检索找回与编码标签和原文引用相关的证据。RAG 在本版本中不是训练模型，也不是建立长期知识库，而是把当前请求中的原文片段重新放进分析上下文。研究者仍然需要确认开放编码，检索分数也只能作为排序信号，不能被解释成统计显著性或因果证据。

## 已知边界

- 当前检索是关键词和中文双字符匹配，不等价于语义向量检索。
- 轴心编码 API 和页面仍未实现，但已经有统一证据类型与无状态检索 API 可供下一 Sprint 使用。
