# QualiCode Sprint 6 交付说明

日期：2026-09-20

## 产品目标

- 轴心编码确认后，研究者可以生成选择性编码。
- 选择性编码输出核心类别、理论故事线、工作命题、关系假设、支持证据、矛盾/反例和复核问题。
- 选择性结果必须经研究者确认后才能进入 `EXPORT`。
- 开放编码在选择性阶段发生修改时，轴心和选择性结果同时 stale，并回到轴心复核入口。

## 后端实现

- 新增 `POST /api/analyze/selective`。
- 请求校验锁定文本版本、开放编码状态、字符位置、轴心类别引用、轴心关系引用和反例证据。
- 使用临时 Chunk/Top-K 检索构造证据上下文，不建立长期索引。
- DeepSeek 单次 JSON 调用，45 秒超时；不提供文件系统、Shell、API Key 或自由循环工具。
- 服务端重新定位模型返回的支持证据、关系证据和矛盾证据；无法定位的内容进入 `unanchoredEvidence`。
- 关系结果统一降级为 `hypothesis`，由研究者继续确认。

## 前端实现

- 轴心确认后显示选择性编码入口。
- 展示核心类别、理论故事线、工作命题、关系假设、支持证据、矛盾/反例和复核问题。
- 增加选择性结果 stale 提示、重新生成按钮和确认按钮。
- 选择性确认后进入 `EXPORT`，当前导出页面留待 Sprint 7。

## 状态规则

```text
AXIAL_REVIEW + confirmed axial
  -> 生成选择性编码
SELECTIVE_CODING + fresh result
  -> 确认选择性编码
EXPORT
```

如果开放编码被修改：

```text
SELECTIVE_CODING
  -> AXIAL_REVIEW
  -> axial stale + selective stale
  -> 重新生成轴心编码
```

## 教学要点

选择性编码不是自动生成“最终理论”。它是对已确认开放编码和轴心类别的更高层组织：核心类别、故事线和命题都需要回到原文，所有关系都只是待研究者验证的假设。受限 workflow 只允许固定输入、一次模型调用、证据定位和用户确认，保证成本、隐私和可解释性边界。
