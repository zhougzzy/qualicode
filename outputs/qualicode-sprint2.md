# QualiCode Sprint 2 交付记录

**日期**：2026-09-19  
**目标**：完成 NVivo 式语义片段人工编码工作区，为下一阶段 AI 开放编码提供稳定的数据结构。

## 已完成

### 产品

- 文本确认后进入开放编码阶段，全文继续只读。
- 用户可以在锁定文本中拖选连续语义片段。
- 创建开放编码时保存原文、字符偏移量、标签和编码状态。
- 编码高亮可以回显，支持多个编码片段重叠。
- 支持查看、修改、软删除和恢复单条编码。
- 开放编码完成后进入“开放编码确认”，未确认的建议不能进入轴心编码。
- 轴心编码后修改开放编码仍会使轴心和选择性分析标记为 `stale`。

### 前端

- 新增 `TextCodingWorkspace` 文本编码组件。
- 使用浏览器 Selection API 获取选区，再转换为相对于 `confirmedText` 的 UTF-16 字符偏移量。
- 使用 `buildHighlightSegments` 将重叠区间拆成可渲染片段，不保存 DOM 状态。
- 手动创建的编码默认为 `accepted`，模拟编码仍保留用于演示后续流程。
- 删除采用软删除，已删除编码可以在当前会话中恢复。

### 后端与契约

- 扩展 `CodeEditRequest.currentStage`，支持开放编码阶段编辑。
- 开放编码阶段编辑不会使下游分析失效；轴心或选择性阶段编辑会返回失效信息。
- 继续复用文本版本和原文证据校验，编码不能写入锁定文本之外的内容。

### 测试

- 新增字符偏移量和高亮分段测试。
- 覆盖重叠编码、删除编码不高亮、无效原文拒绝。
- 覆盖人工编码阶段门禁、完成开放编码、软删除和恢复。
- 覆盖开放编码阶段编辑不产生下游 `stale`。

## 教学要点

1. 不保存浏览器高亮 DOM，而是保存 `start/end` 字符偏移量。
2. 模型或用户提供的 quote 必须重新在锁定文本中定位，不能直接信任偏移量。
3. 重叠标签需要先建立边界集合，再把文本分割成带有多个 `codeIds` 的小片段。
4. `confirmedText` 是不可变研究证据，标签、解释和修订记录属于可变注释层。
