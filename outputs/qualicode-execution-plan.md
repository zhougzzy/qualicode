**日期**：2026-09-19
**配套文档**：

- [PRD](./qualicode-prd.md)
- [技术方案](./qualicode-technical-design.md)

**当前状态**：Sprint 2 已完成锁定文本上的人工语义片段编码、高亮、重叠片段、编辑、软删除、恢复和开放编码确认门禁；类型检查、27 项自动化测试、生产构建和本地页面冒烟验证均已通过。

## 1. 执行方式

采用短周期敏捷开发。每个 Sprint 都完成：

1. 产品目标和用户故事；
2. 前端任务；
3. 后端任务；
4. 测试任务；
5. 教学内容；
6. 可运行的阶段性成果；
7. 复盘和下一轮调整。

没有通过当前 Sprint 的验收标准，不进入下一阶段的 AI 复杂功能。

## 3. Sprint 0：项目骨架和数据契约

### 目标

建立可以联调的单仓库，并先确定领域模型、页面状态和 API 契约。

### 产品任务

- 固化阶段状态机；
- 固化文本锁定规则：文本核对阶段可编辑，用户确认后 `confirmedText` 只读；
- 固化单条编码修订规则：只允许修改该条编码的修订片段和开放编码，不回写整篇文本；
- 固化轴心编码后的修订规则：编辑开放编码时必须同时显示锁定文本中的原文证据；
- 固化下游失效规则：轴心编码完成后修改开放编码，轴心和选择性分析标记为 `stale`；
- 固化重新确认规则：下游分析必须重新生成并再次确认后，才允许继续下一阶段；
- 记录数据声明；
- 确认文件大小和文本长度限制；
- 确认是否添加共享访问码；
- 准备一份虚构访谈样例。

### 前端任务

- 创建应用壳层；
- 创建工作区导航；
- 创建上传、文本核对、编码和分析占位页面；
- 创建 `useReducer` 状态；
- 创建 `sessionStorage` 适配器；
- 创建统一 TypeScript 类型。
- 在状态模型中加入 `textLocked`、`codeEditHistory`、`axialFreshness` 和 `selectiveFreshness`；
- 为文本核对阶段和分析阶段提供不同的编辑能力：前者可编辑全文，后者只读全文；
- 预留单条编码编辑面板，明确展示原文、当前开放编码和下游影响；

### 后端任务

- 创建 Route Handler 占位；
- 创建统一响应结构；
- 创建错误码；
- 创建环境变量读取模块；
- 创建文件大小和文本长度校验模块。
- 冻结 `POST /api/codes/edit` 接口契约；
- 校验 `textVersion` 和 `originalQuote`，确保编码修订不能修改 `confirmedText`；
- 定义编码修订后的失效返回值：`invalidatedStages` 和 `analysisFreshness`；
- 固化开放、轴心、选择性编码的阶段门禁；

### 测试任务

- 状态机跃迁测试；
- 会话保存和刷新恢复测试；
- API 响应结构测试；
- 失败状态测试。
- 测试确认文本后全文编辑入口消失；
- 测试单条编码编辑必须展示原文证据；
- 测试编码修订不会改变 `confirmedText`；
- 测试轴心编码后修改开放编码会使轴心/选择性结果变为 `stale`；
- 测试未重新确认下游分析时不能进入选择性编码；

### 教学主题

- 前后端如何通过接口契约协作；
- 为什么先写领域对象再写页面；
- 无数据库架构的优缺点；
- 不可变研究文本与可修订编码注释的区别；
- 上游编码修改如何触发下游分析失效；

### 退出标准

- `npm run dev` 可以启动；
- 首页可以打开；
- 刷新可以恢复一个模拟会话；
- 类型检查通过；
- 至少有一组自动化测试；
- 数据契约明确区分 `confirmedText`、原文证据、编码修订和分析新鲜度；
- 状态机明确阻止：未锁定文本进入分析、未确认开放编码进入轴心、stale 轴心进入选择性；

## 8. Sprint 5：轴心编码、选择性编码和 Agent 工作流

### 目标

把阶段门禁、RAG 和模型调用串成可解释的受限 Agent。

### 产品任务

- 固化轴心编码字段；
- 固化选择性编码字段；
- 确认“研究假设”标识；
- 确认回退和重新分析规则；
- 设计反例和未解决问题。

### 前端任务

- 开放编码确认按钮；
- 轴心编码入口和页面；
- 轴心结果编辑；
- 选择性编码入口和页面；
- 核心类别和故事线展示；
- 回退和失效提示。

### 后端任务

- `POST /api/analyze/axial`；
- `POST /api/analyze/selective`；
- 工作流编排器；
- 有限工具调用；
- 最大步骤数；
- 证据注入；
- 反例检测；
- 结果 Schema 校验。

### 测试任务

- 未确认开放编码不能进入轴心；
- 未确认轴心不能进入选择性；
- 开放编码修订使下游失效；
- 轴心编码后编辑必须展示原文证据；
- 重新生成并确认轴心编码后才能进入选择性编码；
- 关系无证据时降级；
- Agent 重复调用终止；
- 非因果化表述检查。

### 教学主题

- Workflow 和 Agent 的区别；
- 工具调用边界；
- 人工确认节点；
- 如何避免 Agent 无限循环和过度自主。

### 退出标准

- 三阶段可完整运行；
- 每一阶段都能回指证据；
- 阶段门禁可靠；
- 关系被清楚标记为假设而非事实。

## 10. 当前执行顺序

在开始写代码前先完成：

1. 确认本执行计划；
2. 确认公开网址是否使用共享访问码；
3. 确认文件和文本限制；
4. 进入 Sprint 0；
5. Sprint 0 通过后开始 Sprint 1。
